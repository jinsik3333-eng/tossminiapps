몽글 매치 퍼즐 홈/메뉴/상점 UI 리서치

목표: 첫 화면을 일반 캐주얼 퍼즐 게임의 로비처럼 보이게 하고, 메뉴/상점은 이미지가 깨지거나 텍스트가 겹치지 않는 구조로 정리한다.

TL;DR

  • 홈은 “랜덤 캐릭터 뽑기”보다 “현재 단계, 보상, 시작 CTA”가 먼저 보이는 게임 로비 구조가 더 맞다.
  • 메뉴 버튼은 CSS 버튼을 유지하되 PNG 아이콘만 쓰는 방식이 한글 길이와 반응형에 안전하다.
  • 상점은 아이콘, 아이템명, 효과, 보유량, 가격을 분리해야 작은 화면에서 띄어쓰기와 줄바꿈이 깨지지 않는다.
  • 토스 정책상 시작 직후 전면 안내 모달이나 예상 못 한 광고는 피하고, 시작 전 안내는 홈 카드 안에 노출하는 편이 안전하다.

Wizz 부스터 상점

아이콘과 텍스트, 보유량, 액션 버튼을 분리한 구조는 작은 화면에서도 읽기 쉽다.

반영 방향

  • 홈 상단을 작은 보드 미리보기와 단계 배지로 바꾸고, CTA 문구는 “게임 시작”으로 명확화한다.
  • 시작 전 안내는 바텀시트/모달이 아니라 홈 안의 작은 안내 카드로 넣는다.
  • 메뉴는 홈/다시하기/스테이지/토너먼트를 풀폭으로, 랭킹/상점은 2열, 사운드/조작법은 풀폭으로 정리한다.
  • 상점은 2행 grid-template-area로 바꿔 효과 문구와 보유량이 가격 버튼에 밀리지 않게 한다.
  • 광고 보상은 광고 준비 및 보상 이벤트가 있을 때만 지급하고, “연습 +3”과 보너스 몽글 fallback 보상은 제거한다.

적용 후 확인

홈

단계 배지, 보드 미리보기, 시작 전 안내, “게임 시작” CTA를 첫 화면에 배치했다.

메뉴

홈 버튼을 추가하고 타이틀/닫기 버튼/메뉴 버튼이 겹치지 않도록 패널 여백을 재정리했다.

상점

아이템명, 설명, 보유량, 가격 버튼을 분리해 한글 줄바꿈이 가격 영역에 밀리지 않게 했다.

랭킹/사운드

랭킹 패널과 사운드 패널이 모바일 폭에서 열리고, 가로 오버플로가 없는 것을 확인했다.

토스 문서 근거

  • 다크패턴 방지 정책: 서비스 진입 직후 전면을 가로막는 광고성 인터럽트와 예상 못 한 광고 노출을 피해야 한다.
  • 인앱 광고 2.0 ver2: 보상형 광고는 사용자가 보상을 획득한 이벤트에서만 리워드를 지급해야 한다.
  • 햅틱 진동 실행하기: WebView에서 `generateHapticFeedback`으로 햅틱 타입을 지정해 호출할 수 있다.
