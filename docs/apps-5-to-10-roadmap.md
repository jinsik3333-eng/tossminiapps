# Apps in Toss 5~10호 로드맵

## 방향

1~4호는 소비 습관 테스트/퀴즈형으로 빠르게 승인 요청 가능한 라인업을 만든다. 5호부터는 같은 템플릿을 유지하되, 토스 리워드형 앱처럼 매일 다시 들어올 이유를 더 강하게 넣는다.

공통 구조:

- 홈: 오늘의 사건/미션/수집판
- 1차 액션: 5~60초 테스트 또는 탭 액션
- 결과: 유형별 카드/이미지/짧은 루틴
- 재방문: 7일 또는 30일 기록판
- 광고 CTA: 현금/포인트 지급이 아니라 `광고 보고 루틴 열기`, `추가 단서 받기`, `방어 카드 확인` 같은 콘텐츠 보상형 문구
- 로그인/알림: SDK 가능성은 있으나 초기에는 localStorage 기록 + 로그인 유도 UI로 안전하게 시작

## 5~10호 후보

### 5호. 소비 방어 룰렛

- 앱 ID 후보: `spending-defense-roulette`
- 한 줄: 오늘의 소비 유혹을 룰렛으로 뽑고, 10초 방어 미션을 수행하는 앱
- 핵심 루프:
  - 룰렛 돌리기
  - 오늘의 유혹 카드 획득
  - 10초 방어 선택
  - 광고 보고 방어 루틴 열기
  - 7일 방어 기록
- 장점: 토스 리워드 앱의 룰렛 구조와 가장 닮았지만, 금전 보상 대신 콘텐츠 보상으로 안전하게 운영 가능

### 6호. 냉장고 털기 점심 미션

- 앱 ID 후보: `fridge-lunch-mission`
- 한 줄: 배달/외식 전 냉장고 재료를 골라 오늘의 점심 방어 루틴을 만드는 앱
- 핵심 루프:
  - 재료 3개 탭
  - 오늘의 조합 카드
  - 배달 유혹 방어 체크
  - 광고 보고 3분 메뉴 루틴 열기
- 장점: 금융상품/민감 영역이 아니고 생활 루틴이라 심사 리스크 낮음

### 7호. 영수증 몬스터 잡기

- 앱 ID 후보: `receipt-monster-catcher`
- 한 줄: 오늘의 영수증/소비 기억을 직접 골라 과소비 몬스터를 잡는 앱
- 핵심 루프:
  - 소비 항목 직접 선택
  - 몬스터 HP 감소
  - 결과 몬스터 카드
  - 30일 몬스터 도감
- 장점: 2호 `헛돈 방어전`의 게임성을 확장하기 좋음

### 8호. 구독 결제일 캘린더 챌린지

- 앱 ID 후보: `subscription-calendar-challenge`
- 한 줄: 자동조회 없이 직접 입력/선택으로 결제일 기억력을 점검하는 앱
- 핵심 루프:
  - 오늘의 결제일 퀴즈
  - 모르는 구독 후보 표시
  - 광고 보고 점검 체크리스트 열기
  - 7일 결제일 기록
- 장점: 3호와 연결되지만 좀 더 루틴형/재방문형

### 9호. 퇴근길 선택 게임

- 앱 ID 후보: `afterwork-choice-game`
- 한 줄: 퇴근길 3초 선택으로 택시/배달/편의점 유혹을 막는 초단기 게임
- 핵심 루프:
  - 오늘의 퇴근길 상황
  - 3초 선택
  - 방어/실패 애니메이션
  - 광고 보고 리벤지 카드 열기
- 장점: 게임앱 전환의 브릿지. 구현 난이도 낮고 반복 사용성이 높음

### 10호. 월급날 생존 키트

- 앱 ID 후보: `payday-survival-kit`
- 한 줄: 월급날 첫 24시간에 돈이 새는 행동을 막는 체크리스트/미니게임
- 핵심 루프:
  - 월급날 행동 선택
  - 생존 키트 수집
  - 지출 유혹 방어 카드
  - 7일 월급 보호 기록
- 장점: 1호/4호와 연결되고, 월급날 시즌성 이벤트로 재방문 유도 가능

## 게임앱 전환 전략

### 1단계: 게임처럼 보이는 테스트형

- 1~4호에 이미 반영 중인 구조
- 탭 액션, 단서/패치/방패 수집, 7일 기록, 광고 CTA 중심
- Apps in Toss 심사 리스크가 낮고 빠르게 양산 가능

### 2단계: 라이트 게임형

- 5~10호 중 5호/7호/9호를 우선 게임형으로 제작
- 룰렛, HP, 타이머, 도감, 연속 기록처럼 게임 문법 사용
- 보상은 현금/포인트가 아니라 카드/루틴/도감/기록

### 3단계: 진짜 게임앱 템플릿

SDK에서 확인한 후보 API:

- `getUserKeyForGame`
- `getAnonymousKey`
- `getGameCenterGameProfile`
- `contactsViral`
- `grantPromotionReward`
- `appLogin`
- `requestPermission`

적용 순서:

1. localStorage 기반 점수/기록으로 MVP 출시
2. 토스 로그인/게임 user key 사용 가능 여부 확인
3. 게임 프로필/친구초대/랭킹 가능성 검토
4. 프로모션 보상 API는 심사/정책/콘솔 설정 확인 후 별도 적용

## 우선순위 제안

- 5호: `소비 방어 룰렛`
- 6호: `영수증 몬스터 잡기`
- 7호: `퇴근길 선택 게임`
- 8호: `냉장고 털기 점심 미션`
- 9호: `구독 결제일 캘린더 챌린지`
- 10호: `월급날 생존 키트`

이 순서가 좋은 이유:

- 5~7호에서 게임성을 빠르게 테스트할 수 있음
- 8~10호는 생활 루틴형이라 심사 안전성과 앱 수 확장에 유리함
- 성공 지표가 좋은 게임형을 이후 별도 템플릿으로 분리하기 쉬움
