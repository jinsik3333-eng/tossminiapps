# Apps in Toss 게임 미니앱 진입/출시 가이드 정리

작성일: 2026-05-04
대상: Toss 미니게임 라인, 1호 후보 `몽글 매치 퍼즐`
근거: Apps in Toss 공식 문서/AX 검색 결과

## 1. 공식 문서에서 확인한 게임 전용 항목

### 게임 출시 가이드

공식 문서 위치:
- `https://developers-apps-in-toss.toss.im/checklist/app-game.md`
- `https://developers-apps-in-toss.toss.im/checklist/_app-game-must.md`
- `https://developers-apps-in-toss.toss.im/checklist/_app-game-choice.md`

확인된 큰 분류:
- 접속 및 사운드
- UX 및 내비게이션 바
- 유저 식별키 발급
- 보안 및 안정성
- 서비스 이용 동작
- 선택 기능: 인앱 결제, 인앱 광고, 공유 리워드, 웹보드 게임

주의:
- 현재 공개 llms 문서에는 상세 체크 문항이 일부 제목 수준으로만 제공된다.
- 실제 검토 요청 전에는 콘솔/최신 문서에서 게임 출시 체크리스트를 다시 확인한다.

### 게임 프로필 & 리더보드

공식 문서 위치:
- `https://developers-apps-in-toss.toss.im/game-center/intro.md`
- `https://developers-apps-in-toss.toss.im/game-center/develop.md`
- `https://developers-apps-in-toss.toss.im/game-center/qa.md`

핵심:
- 게임 프로필과 리더보드는 게임 서비스에서만 제공되는 기능이다.
- 게임 프로필은 사용자가 게임 시작 전에 최초 1회 등록한다.
- 프로필을 만들지 않은 사용자는 게임을 진행할 수 없어야 한다.
- 프로필 생성 후에는 재접속 시 환영 메시지를 노출한다.
- 점수 제출은 게임 시작 시점이 아니라 게임 종료 뒤 호출한다.
- 리더보드를 열면 미니앱은 백그라운드 상태로 전환되고, 돌아오면 포그라운드로 복귀한다.

### 게임 센터 관련 API

WebView 기준 공식 문서에서 확인한 API:

- `submitGameCenterLeaderBoardScore({ score: string })`
  - 게임 종료 시점에 점수 제출
  - 토스앱 5.221.0 이상 지원
  - 프로필 생성 전 호출하면 오류 가능
  - 미니앱 정보 승인이 안 된 상태에서는 `LeaderBoard not found` 가능
  - 샌드박스 점수는 실제 서비스 리더보드에 반영되지 않음

- `openGameCenterLeaderboard()`
  - 사용자가 순위를 확인하도록 리더보드 WebView 호출
  - 게임 진입 직후 바로 호출하면 프로필 WebView와 겹칠 수 있음
  - 호출 시 미니앱이 백그라운드로 전환되므로 게임 상태 저장 필요

- `getUserKeyForGame()`
  - 게임 미니앱 전용 유저 식별키 발급
  - 비게임 카테고리에서 호출하면 `INVALID_CATEGORY`
  - 토스앱 5.232.0 이상 지원
  - 반환 hash는 게임사 내부 식별용이며 토스 서버 직접 요청용이 아님

- `grantPromotionRewardForGame({ params: { promotionCode, amount } })`
  - 게임 미니앱 내 토스 포인트 지급/혜택탭 노출용
  - 게임 카테고리에서만 호출 가능
  - 토스앱 5.232.0 이상 지원
  - 실제 프로모션 시작 전 테스트용 프로모션 코드로 최소 1회 이상 호출 필요
  - 비즈월렛/예산/사업자/콘솔 설정이 필요하므로 초기 MVP 카피에서는 포인트 지급을 약속하지 않는다.

## 2. 실제 Toss 게임 화면에서 관찰한 UX와 공식 가이드의 관계

공식 가이드가 직접 강제하는 쪽:
- 게임 프로필 생성/확인
- 프로필 생성 전 게임 진행 제한
- 게임 종료 후 점수 제출
- 리더보드 열기
- 리더보드 호출 시 백그라운드/포그라운드 상태 관리
- 게임 카테고리 전용 API 조건
- 출시 체크리스트 준수

게임들이 관습적으로 넣는 쪽:
- 퍼블리셔/스튜디오 스플래시
- 게임 로고/타이틀 화면
- 전체이용가 등급 배지
- 스테이지맵
- 토너먼트/랭킹/상점/설정 메뉴
- 게임다운 고채도/두꺼운 외곽선/큰 버튼 UI

판단:
- “첫 화면 디자인을 반드시 이렇게 만들어라”라는 공식 템플릿보다는, 게임 센터/리더보드/프로필/출시 체크 중심 가이드가 핵심이다.
- 따라서 우리 게임은 공식 필수 흐름을 지키고, 실제 인기 게임의 관습적 첫 화면을 참고해 게임다운 UI를 구성한다.

## 3. 우리 게임의 권장 진입 플로우

### 0. 앱/게임 로딩

목표:
- 2~3초 안에 첫 게임 UI 표시
- 5초 초과 시 개선 필요

화면:
- 로고 또는 간단한 캐릭터
- `게임 준비 중`
- 가벼운 진행 표시

구현 원칙:
- 첫 화면 리소스는 가볍게 유지
- 보드/핵심 UI 먼저 렌더링
- 무거운 이미지/사운드/스테이지 데이터는 지연 로딩

### 1. 게임 프로필 확인

공식 게임 센터 연동 시:
- 프로필이 없으면 프로필 생성 모달/흐름 노출
- 프로필 생성 완료 전에는 `시작하기` 비활성 또는 차단
- 프로필이 있으면 `반가워요, ○○님` 환영 메시지

초기 로컬/브라우저 MVP fallback:
- SDK 미지원 환경에서는 `게스트 플레이` 또는 mock profile 사용
- 실제 토스 QA에서는 프로필 생성 모달 노출 여부를 별도 확인

### 2. 자체 게임 타이틀 화면

필수 요소:
- 게임명
- 한 줄 규칙
- `바로 시작`
- `스테이지`
- `랭킹`
- `설정`
- 하단 배너 광고 슬롯

권장 카피:
- `같은 몽글이 3개를 맞춰 목표 점수를 채워보세요`
- `오늘의 스테이지에 도전하기`

### 3. 첫 플레이 튜토리얼

최초 1회만 노출:
- `같은 몽글이 3개를 맞추면 사라져요.`
- `이동 횟수 안에 목표 점수를 채우면 클리어!`

원칙:
- 1~2문장 이하
- 화면을 가리지 않음
- 바로 플레이 가능해야 함

### 4. 게임 플레이 화면

구성:
- 상단 HUD: 이동 횟수 / 목표 점수 / 현재 점수
- 중앙: 6x6 또는 7x7 보드
- 하단: 부스터/힌트/광고 슬롯
- 우상단: 메뉴

상태 저장:
- 리더보드/광고/백그라운드 전환에 대비해 현재 스코어, 남은 이동, 보드 상태 저장

### 5. 게임 종료 화면

구성:
- 성공/실패
- 점수
- 별 개수
- 다시하기
- 다음 스테이지
- 랭킹 보기
- 광고 보고 이동 +3 또는 이어하기

API 호출:
- 종료 시 1회만 `submitGameCenterLeaderBoardScore`
- 중복 제출 방지 플래그 필요
- `랭킹 보기` 버튼에서 `openGameCenterLeaderboard`

## 4. MVP 적용 범위

1차 MVP에 넣을 것:
- 게임 로딩/타이틀 화면
- mock profile 상태와 환영 메시지 영역
- 6x6 보드
- 같은 타일 3개 매치/제거
- 이동 횟수/목표 점수/현재 점수
- 성공/실패 결과 화면
- 랭킹 버튼 UI + SDK 미지원 fallback
- 하단 배너 광고 슬롯 자리
- 보상형 광고 CTA 자리: `광고 보고 이동 +3`

1차 MVP에서 보류:
- 실제 포인트 지급 문구
- 실제 프로모션 지급 API
- 복잡한 상점/IAP
- 토너먼트 실제 운영
- 대형 사운드/무거운 애니메이션
- 웹보드/사행성 인접 장르

## 5. QA 체크리스트

### 공식 게임 센터 QA

- 최초 진입 시 프로필 생성 모달이 노출되는가?
- 프로필 생성 완료 전 게임 진행이 막히는가?
- 프로필 생성 후 환영 메시지가 노출되는가?
- 재접속 시 프로필/환영 상태가 유지되는가?
- 게임 종료 후에만 점수 제출 API를 호출하는가?
- 동일 플레이에서 점수 중복 제출이 방지되는가?
- 네트워크 오류/타임아웃 시 대체 흐름이 있는가?
- 리더보드 진입 시 화면 겹침 없이 정상 표시되는가?
- 리더보드에서 복귀했을 때 게임 상태가 유지되는가?
- 포그라운드/백그라운드 전환 시 UI 깨짐이나 리셋이 없는가?

### 우리 프로젝트 QA

- 390px 모바일 폭에서 모든 텍스트가 읽히는가?
- 첫 화면 CTA가 접힘 없이 보이는가?
- 보드 타일이 손가락으로 누르기 충분한가?
- 광고 슬롯이 게임 진행 버튼을 가리지 않는가?
- `포인트`, `현금`, `돈 준다`처럼 공식 프로모션 없는 보상 약속 카피가 없는가?
- 빌드 결과 `.ait` 파일이 생성되는가?

## 6. 결정

`몽글 매치 퍼즐`은 일반 미니앱 템플릿이 아니라 `game-template` 계열로 분리한다.

첫 구현 목표:
- WebView/React 기반 캐주얼 게임 MVP
- 공식 게임 센터 연동을 위한 adapter/fallback 구조
- 실제 Toss 게임 화면과 가까운 진입/타이틀/스테이지/랭킹 UI shell
- 광고/리더보드/프로필은 초기부터 자리와 상태 흐름을 잡되, 승인/콘솔 설정이 필요한 기능은 안전한 fallback으로 둔다.
