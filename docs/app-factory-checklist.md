    68|7. 비슷한 기능은 같은 패턴으로 반복하기

    70|### 적용 방식
    71|
    72|- 첫 화면에는 “무엇을 하는 앱인지”와 “지금 누를 버튼”이 바로 보여야 한다.

    76|- 앱별 차이는 콘텐츠와 캐릭터만 바꾸고, 버튼/피드백/광고 보상 패턴은 공통화한다.

## 2026-05-29 추가 체크: 몽글 게임 재미/광고 UX

- [ ] 첫 화면에 `게임 방법` 카드가 있고, 플레이어가 무엇을 누르고 무엇을 피하거나 고르는지 한 문장으로 보인다.
- [ ] 퍼즐/스테이지형 게임 첫 화면은 단순 캐릭터 소개가 아니라 현재 단계, 다음 보상, 보드/플레이 미리보기, 명확한 `게임 시작` CTA가 보이는 로비형 화면으로 구성한다.
- [ ] 시작 전 광고/사운드/진동 안내는 사용자를 막는 모달보다 첫 화면 안의 짧은 안내 카드로 제공한다.
- [ ] 플레이 화면에 현재 단계와 다음 단계가 보인다. 단계가 없는 단순 무한 루프처럼 보이면 출시 전 보강한다.
- [ ] 단계가 실제 플레이에도 영향을 준다. 속도, 장애물 비율, 안전구간, 맵 배치, 정답 조건, 보상 주기 중 하나 이상이 단계별로 달라지는지 확인한다.
- [ ] 획득/충돌/정답/오답/벽 부딪힘 같은 핵심 이벤트마다 즉시 피드백이 있다.
- [ ] 3매치류는 4개/5개/동시 가로세로 매치에 점수 배율, 임팩트, 아이템 보상 같은 차등 보상이 있고 순수 로직 테스트로 잠근다.
- [ ] 3매치류는 가능한 인접 스왑이 0개가 되면 자동으로 셔플하고, 셔플 후 즉시 매치가 없는 상태와 다음 수 1개 이상을 보장한다.
- [ ] 3매치류 특수 아이템은 키보드 이모지가 아니라 앱 톤에 맞춘 이미지/SVG 아이콘으로 보인다. 가로 스윕, 세로 스윕, 폭탄, 같은 블록 삭제, 셔플은 상점/보상 경로까지 연결한다.
- [ ] 플레이 중 아이템 독은 390px에서 각 버튼 44px 이상을 유지한다. 아이템 독과 광고/상점 CTA를 같은 행에 무리하게 넣지 않는다.
- [ ] 캐주얼 게임 메뉴는 다시하기, 스테이지, 토너먼트, 랭킹, 상점, 사운드, 조작법 중 필요한 항목을 실제 액션으로 연결한다.
- [ ] 메뉴 아이콘/닫기/타이틀 장식은 키보드 이모지나 CSS 도형이 아니라 앱 톤에 맞춘 PNG 에셋으로 보인다. 단, 버튼 자체와 한글 텍스트는 반응형을 위해 CSS/live DOM으로 유지한다.
- [ ] 게임형 UI의 주요 버튼은 유광 하이라이트, 갈색 70~85% 외곽선, 하단 그림자를 유지해 손가락으로 누르는 느낌을 준다.
- [ ] 관찰/탐정류 게임은 단일 표식 찾기로 끝나지 않고 2개 이상의 단서를 조합하게 한다. 정답 role/class가 화면 스타일로 노출되지 않는지도 확인한다.
- [ ] 캐릭터는 SVG 도형 대체가 아니라 앱별 PNG 에셋을 사용하고, 390px에서 표정/역할 소품이 보인다.
- [ ] 하단 배너 슬롯은 모든 상태에 있고, 다음 판 광고 게이트는 결과 이후 자연스러운 재시작 맥락에만 둔다.
- [ ] 출시 번들에 `ait-ad-test` 문자열이 없고, 실제 광고 그룹 ID는 `VITE_TOSS_BANNER_AD_GROUP_ID`, `VITE_TOSS_REWARDED_AD_GROUP_ID`로만 주입한다.
- [ ] 실제 광고 그룹 ID가 비어 있거나 광고가 준비되지 않은 로컬 QA에서는 광고 placeholder나 연습 보상 버튼을 노출하지 않고, 준비 중 메시지나 즉시 가능한 일반 액션만 보인다.
- [ ] 보상형 광고 보상은 SDK의 완료/보상 이벤트에서만 지급한다. 로컬 fallback은 제품 규칙과 다른 `연습 보상`으로 노출하지 않는다.
- [ ] 진동은 Apps in Toss `generateHapticFeedback`을 우선 호출하고, 미지원 브라우저에서만 `navigator.vibrate`를 보조로 사용한다.
