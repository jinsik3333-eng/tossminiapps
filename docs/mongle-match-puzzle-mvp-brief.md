# 몽글 매치 퍼즐 MVP Brief

작성일: 2026-05-04
앱 유형: Apps in Toss 게임 미니앱
목표: Toss 미니게임 1호로 검증 가능한 3매치 퍼즐 MVP 제작

## 1. 한 줄 정의

`몽글 매치 퍼즐`은 한 판마다 100종 랜덤 몽글을 모으고, 1% 유니크 몽글의 점수 보너스로 리더보드에 도전하는 초간단 모바일 퍼즐 게임이다.

## 2. 왜 이 앱인가

Toss 게임 영역에서 확인한 상위 게임들은 일반 테스트형 미니앱과 사용 양상이 다르다.

참고 패턴:
- 정글 매치 퍼즐
- 애니팡2
- 스테이지/랭킹/상점/토너먼트형 캐주얼 게임

선택 이유:
- 3매치 퍼즐은 즉시 이해된다.
- 광고 보상 지점이 자연스럽다.
- 스테이지/랭킹/상점 더미를 붙이기 쉽다.
- 사행성/금융상품/의료/상담 등 정책 리스크가 낮다.
- 첫 게임 템플릿으로 재사용 가능하다.

## 3. 핵심 사용자 경험

사용자는 토스 게임 탭/혜택 탭에서 들어와 10~30초 안에 한 판을 시작한다.

기대 흐름:
1. 게임 로딩
2. 게임 프로필 확인 또는 mock profile fallback
3. 홈에서 현재 도감 수집률과 `1% 유니크 점수 2배` 규칙 확인
4. 6x6 보드에서 같은 타일 3개 매치
5. 이동 횟수 안에 목표 점수 달성
6. 결과 화면에서 랜덤 몽글 획득
7. 기본 점수에 희귀도 보너스를 더한 리더보드 점수 제출
8. 필요하면 광고 보고 이동 +3 또는 보너스 몽글 조각 획득

## 4. MVP 화면

### 1) 로딩/브랜드 화면

목적:
- 게임 앱처럼 느껴지게 만들기
- 첫 프레임을 빠르게 표시

구성:
- 몽글 캐릭터/로고 영역
- `게임 준비 중`
- 짧은 로딩 바

### 2) 게임 타이틀 홈

구성:
- 게임명: `랜덤 몽글 모으기`
- 규칙: `100종 몽글 도감을 채우고, 1% 유니크 몽글로 리더보드 점수 2배!`
- 수집 현황: `n/100종 수집`, 총 조각 수
- 도감 미리보기: 대표 12칸 + `+89 도감에서 보기`
- 주요 CTA: `오늘 몽글 찾기`
- 보조 CTA: `한 판 도전`, `랭킹`, `도감`
- 환영 메시지: `반가워요, 플레이어님`
- 하단 배너 광고 슬롯

### 3) 튜토리얼 오버레이

최초 1회:
- `같은 몽글이 3개를 맞추면 점수가 올라요.`
- `이동 횟수 안에 목표 점수를 채우면 클리어!`

### 4) 플레이 화면

구성:
- 상단 HUD
  - 이동 횟수
  - 목표 점수
  - 현재 점수
- 6x6 보드
- 하단 부스터 바
  - 힌트
  - 이동 +3
  - 랭킹
- 하단 배너 광고 슬롯

### 5) 결과 화면

성공/실패 공통:
- 결과 화면에서 랜덤 몽글 1종 획득
- 희귀도 표시: 커먼/레어/에픽/유니크
- 기본 점수
- 희귀도 보너스
- 리더보드 점수
- 도감 누적 조각 수
- 리더보드 제출 상태
- `랭킹 보기`
- `광고 보고 보너스 몽글`

성공:
- `다음 몽글 찾기`

실패:
- `다시 도전`
- `광고 보고 이동 +3`

## 5. 게임 규칙 MVP

### 보드

- 6x6 그리드
- 타일 종류 5개
- 타일은 캐릭터/색상으로 구분
- 모바일에서 한 칸이 충분히 커야 함

### 조작

MVP에서는 구현 안정성을 위해 `인접 타일 교환` 방식으로 시작한다.

- 타일 1개 선택
- 인접 타일 선택 시 교환
- 교환 후 가로/세로 3개 이상 같은 타일이면 제거
- 매치가 없으면 원위치

### 점수

기본 점수:
- 3개 매치: 30점
- 4개 매치: 60점
- 5개 이상 매치: 100점
- 연쇄 매치: combo 배수는 2차에서 추가

리더보드 점수:
- 커먼 몽글: 기본 점수 x1.0
- 레어 몽글: 기본 점수 x1.2
- 에픽 몽글: 기본 점수 x1.5
- 유니크 몽글: 기본 점수 x2.0
- 결과 화면에서 `기본 점수 + 희귀도 보너스 = 리더보드 점수`를 명확히 보여준다.

랜덤 몽글 출현률 MVP:
- 커먼 64%
- 레어 25%
- 에픽 10%
- 유니크 1%

100종 도감 MVP:
- 25개 테마 × 4개 변형 = 100종
- 유니크 캐릭터는 여러 종이 있어도 전체 유니크 카테고리 출현률은 1%로 고정
- 상세 디자인 기준은 `docs/mongle-collectible-design-system.md`와 `docs/mongle-premium-art-direction.md`를 따른다.
- 앱 asset path는 `/mongles/premium/{001-100}-{series}-{variant}.webp`로 고정하고, 실제 이미지 생성 전에는 placeholder shell을 표시한다.
- 내부 제작 단계는 대표 12종 톤 확정 후 100종 확장이지만, 사용자에게 보이는 앱 카피는 항상 `100종 도감` 기준으로 유지한다.

### 스테이지

MVP 스테이지 1개:
- 이동 횟수: 20회
- 목표 점수: 600점

더미 확장:
- Stage 2~20 locked node UI
- 실제 플레이는 Stage 1만 우선

- `광고 보고 힌트 열기`
- `광고 보고 보너스 몽글`

금지/보류 카피:
- `포인트 지급`
- `돈 받기`
- `현금 보상`
- `토스 포인트 무조건 지급`

배치:
- 홈 하단 배너
- 플레이 하단 배너
- 결과 화면 보상형 CTA

## 7. 게임 센터 연동 설계

### adapter 구조

`src/lib/tossGameCenter.ts` 같은 adapter를 둔다.

필요 함수:
- `getGameProfileOrFallback()`
- `submitScoreOnce(score, playId)`
- `openLeaderboardSafe()`
- `getGameUserKeyOrFallback()`

원칙:
- 브라우저/로컬에서는 mock fallback
- SDK 미지원 시 사용자 흐름을 막지 않음
- 실제 점수 제출은 결과 화면에서 1회만
- 리더보드 호출 전 현재 게임 상태 저장

### 공식 API 주의점

- `submitGameCenterLeaderBoardScore`는 게임 종료 후 호출한다.
- 점수는 string으로 전달한다.
- 토스앱 5.221.0 미만에서는 `undefined` 가능.
- 프로필 생성 전 제출하면 오류 가능.
- 승인 전에는 `LeaderBoard not found` 가능.
- `openGameCenterLeaderboard` 호출 시 미니앱이 백그라운드로 전환된다.
- `getUserKeyForGame`과 `grantPromotionRewardForGame`은 토스앱 5.232.0 이상 및 게임 카테고리 조건을 고려한다.

## 8. 디자인 방향

일반 테스트형 미니앱과 다르게 게임다운 톤을 쓴다.

원칙:
- 큰 타일
- 두꺼운 외곽선
- 고채도 색상
- 둥글고 광택 있는 버튼
- 상단 HUD는 매우 읽기 쉽게
- 작은 설명 텍스트 금지
- 실제 모바일 390px에서 읽히는 크기 유지

피할 것:
- 금융 앱처럼 너무 흰 카드만 많은 화면
- 설명형 카드뉴스 같은 UI
- 너무 작은 라벨/장식 텍스트
- 보드보다 광고가 더 커 보이는 구조
- 돈/포인트 보장처럼 보이는 카피

## 10. 완료 기준

MVP 완료 조건:
- 사용자가 홈에서 바로 게임을 시작할 수 있다.
- 보드에서 인접 타일을 교환할 수 있다.
- 3개 이상 매치가 제거되고 점수가 오른다.
- 이동 횟수가 줄어든다.
- 목표 점수 달성 시 성공 결과가 뜬다.
- 이동 횟수 소진 시 실패 결과가 뜬다.
- 결과 화면에 랜덤 몽글 획득/희귀도 보너스/리더보드 점수가 있다.
- 홈에 100종 도감 수집률과 대표 도감 미리보기가 있다.
- 결과 화면에 랭킹/광고 CTA 자리가 있다.
- 로컬 브라우저에서도 SDK fallback으로 흐름이 깨지지 않는다.
- `npm run build`가 성공한다.
