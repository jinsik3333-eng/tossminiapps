# Common Template Decisions

## 공통 리텐션/광고 구조

- 모든 앱은 홈에 알림/로그인 nudge를 둔다.
- 모든 앱은 보조 체리피킹 메뉴를 둔다.
- 광고 CTA는 현금/포인트/보상 표현 대신 `루틴 카드`, `추가 단서`, `체크리스트` 같은 콘텐츠 보상형 표현을 사용한다.
- 결과 화면에는 오늘의 단서, 오늘의 루틴, 반복 CTA, 광고 후 추가 콘텐츠를 둔다.

## 앱 타입별 기본 구조

- 룰렛형: 중앙 큰 룰렛 회전 → 멈춤 → 선택/결과 reveal.
- 탭 게임형: 홈 → 탭 HP 감소 → 포획/완료 → 결과 루틴 카드.
- 테스트형: 질문 4~6개 → 결과 유형 → 결과별 이미지/루틴 카드.
- Toss 캐주얼 게임형: 로딩/프로필 확인 → 랜덤 수집/점수 보너스가 보이는 게임 홈 → 1회 튜토리얼 → 플레이 HUD/보드 → 랜덤 획득 결과/랭킹/보상형 광고 CTA. 일반 미니앱 TDS 카드보다 큰 보드, 두꺼운 외곽선, 고채도 버튼, 게임센터 adapter를 우선한다.
- 3매치류 보드 조작: 모바일 기본값은 스와이프/드래그로 인접 칸 교체, 클릭-클릭은 보조 조작으로 유지한다. 타일에는 `touch-action: none`을 적용해 스크롤 제스처와 충돌을 줄인다.

## lane defense 게임 템플릿 결정

- Toss 캐주얼 디펜스형 기본 흐름은 `home → tutorial/profile gate → play → result`로 둔다.
- 홈 리텐션 요소는 오늘 웨이브, 최근 7일 기록, 수집 진행률, 리더보드/fallback 상태, 하단 광고 슬롯이다.
- 플레이는 30초·HP 5·3 lane·탭 제거·콤보 8 스킬 1회 구성을 MVP 기본값으로 한다.
- CSS monster/token 방식으로 toy/clay 느낌을 만들고, 대량 이미지 생성은 대표 샘플 승인 전까지 보류한다.
- Game Center adapter는 local/sandbox/unsupported에서 inline 메시지만 보여주고 게임 진행을 막지 않는다.

## 2026-05-07 — 테스트형 앱 보조 메뉴 위치

- 결정: 테스트형 앱의 보조 메뉴/체리픽 메뉴는 intro가 아니라 result 하단에 둔다.
- 이유: 사용자는 먼저 진단 완료와 결과 확인을 기대하므로, 시작 전 보조 메뉴는 진입 집중도를 낮춘다.
- 구현 규칙: 보조 메뉴 컴포넌트는 label 배열이 아니라 `{ label, onClick }` 액션 배열을 받게 해 실기기 테스트에서 무동작 버튼이 생기지 않게 한다.

## 2026-05-07 — WebView 앱 브랜드 아이콘 공통 규칙

- 결정: 모든 WebView 미니앱은 `public/app-icon.png`를 앱별 고유 아이콘으로 두고, `granite.config.ts`의 `brand.icon`은 `https://{appName}.apps.tossmini.com/app-icon.png` 형식으로 채운다.
- 이유: `brand.icon` 빈 값은 Apps in Toss 검수에서 콘솔 등록 아이콘과 불일치로 반려될 수 있다.
- 운영: AIT 업로드 전 콘솔 앱 정보의 브랜드 아이콘에 같은 PNG를 업로드하고, `npm run build` 산출물을 새로 등록한다.

## 2026-05-07 — 보조 메뉴와 광고 게이트 분리

- 결정: 결과 화면의 보조 메뉴 버튼은 광고 영상으로 보내지 않는다. 광고는 `광고 보고 ...`처럼 명시된 단일 보상 CTA에서만 선택적으로 실행한다.
- 이유: 여러 보조 메뉴가 모두 광고로 이어지면 사용자는 무동작/광고 유도 UI로 인식한다. 검수/UX 관점에서도 앱 기능과 광고 지점이 분리되어야 한다.
- 구현 규칙: `CherryPickMenu`류 컴포넌트는 `string[]`가 아닌 `{ label, onClick }[]`를 받고, 모든 버튼에 실제 액션을 연결한다. 제작자 관점 문구(`매일 들어올 이유`, `리텐션`)와 보조 메뉴 내부 `AD ·` 문구는 사용하지 않는다.

## 2026-05-08 — 혜택 루프와 배너 수익화 기본형

- 결정: `패치 붙이기` 같은 모호한 버튼명 대신 `혜택 루틴 열기 n/3`처럼 누르면 무엇이 열리는지 버튼에 직접 쓴다.
- 결정: 결과 화면 보조 메뉴는 `오늘의 보조 메뉴`가 아니라 `결과 활용하기`처럼 사용자 가치 중심 이름을 쓴다.
- 결정: 수익화는 화면별 상시 배너 + 명시적 보상형 CTA를 조합한다. 배너는 시작/문항/결과 화면에 배치하고, 보상형 광고는 상세 처방/배지 완성처럼 사용자가 광고 시청을 예상할 수 있는 버튼에만 연결한다.
- 근거: Apps in Toss 배너 광고 문서는 WebView 배너 컨테이너 width 100%, 고정형 height 96px 권장 및 SDK 초기화/attach/destroy 흐름을 안내한다.
## UI 표준: 한 화면 한 행동 원칙

토스 미니앱의 모든 일반앱/비게임 앱 화면은 아래 7개 원칙을 기본 판정 기준으로 삼는다.

1. 첫 화면에서 앱의 목적을 바로 알 수 있게 하기
2. 주요 행동 버튼을 하나만 또렷하게 두기
3. 입력은 최대한 줄이고 기본값을 제공하기
4. 화면 이동 흐름을 짧게 만들기
5. 저장·로딩·실패·완료 상태 피드백을 즉시 보여주기
6. 빈 화면·에러 화면에도 다음 행동을 넣기
7. 비슷한 기능은 같은 패턴으로 반복하기

### 적용 방식

- 첫 화면에는 “무엇을 하는 앱인지”와 “지금 누를 버튼”이 바로 보여야 한다.
- 광고/리워드/알림/크로스앱 이동은 사용자의 다음 행동을 흐리게 하지 않고, 보상 맥락에서 제공한다.
- 리워드 허브형 화면도 한 번에 여러 버튼을 난사하지 않고, 대표 CTA 1개와 보조 행동 묶음으로 구성한다.
- 각 앱의 결과 화면은 “결과 확인 → 광고 보고 보상/루틴 받기 → 다른 앱/내일 재방문” 흐름을 짧게 유지한다.
- 앱별 차이는 콘텐츠와 캐릭터만 바꾸고, 버튼/피드백/광고 보상 패턴은 공통화한다.
