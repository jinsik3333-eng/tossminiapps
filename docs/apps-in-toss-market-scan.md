# Apps in Toss 시장/성공사례 스캔

조사일: 2026-05-02
범위: 공개 웹 문서, Toss 공식 블로그/토스피드/개발자센터, 언론 기사. 실제 토스 앱 내부의 실시간 인기 순위는 웹에서 완전 공개되어 있지 않아, 공개 사례 기반으로 해석한다.

## 1. 공개 사례에서 확인된 성공 패턴

### 용사단키우기
- 유형: 머지형 RPG / HTML5 게임
- 성과: 앱인토스에서 70일 만에 100만 유저, 누적 매출 1억 5천만 원(토스 공식 블로그)
- 성공 포인트:
  - 기존 게임을 앱인토스에 맞게 최적화
  - 설치 없이 바로 플레이
  - 성장/강화/머지 루프가 짧고 반복적
  - 게임 카테고리와 토스 홈 노출 구조 수혜

### 거지키우기
- 유형: 방치형 클리커 게임
- 성과: 실시간 인기 게임 1위, 누적 매출 1억 원 근접(토스 공식 블로그)
- 성공 포인트:
  - 원래 대중 인지도가 있는 IP/컨셉
  - 화면 터치 → 재화 획득 → 성장이라는 즉각 보상 루프
  - 제목 자체가 강한 후킹
  - 짧은 세션과 재방문에 적합

### 애니팡2 웹버전
- 유형: 퍼즐 게임
- 성과: 토스 미니앱 전체 인기 순위 6위, 퍼즐 부문 3위, 최근 2주 하루 평균 5만여 명 이용, 누적 플레이 시간 1만 시간 돌파(언론 보도)
- 성공 포인트:
  - 기존 대중 IP
  - HTML5 기반으로 설치 없이 플레이
  - 친구/메신저 등 복잡 요소 제거, 퍼즐 플레이 집중
  - 짧은 세션에 최적화

### 두쫀쿠맵
- 유형: 트렌드 기반 재고 지도/생활 편의
- 성과: 런칭 즉시 인기 미니앱 1위, 한 달 MAU 108만(토스 공식 블로그)
- 성공 포인트:
  - 트렌드/품절/헛걸음이라는 명확한 불편
  - 앱인토스 팀과 통화 후 하루 만에 출시
  - SNS 바이럴과 토스 내부 유입 결합
  - 실시간성/희소성/지도라는 즉시 효용

### 디스팟
- 유형: 할인 정보/쿠폰 큐레이션
- 성과: 오픈 첫 달 월 매출 1,000만 원(토스 공식 블로그)
- 성공 포인트:
  - 할인 코드 확인 → 구매 → 수수료 정산 구조
  - 개발 비전공자도 하루 5시간씩 5일 만에 완성
  - 토스 유저에게 “혜택” 맥락이 잘 맞음
  - 콘텐츠/제휴/카테고리 확장 가능

### 로빈 사례
- 유형: 여러 나노앱/사진 변환 등
- 성과: 비개발자가 2개월 만에 앱 21개 출시, 일부 CTR 20%대 사례(토스 공식/언론)
- 성공 포인트:
  - 앱 이름을 길게 지어 리스트에서 눈에 띄게 함
  - 바이브코딩으로 빠른 다작
  - 개발보다 “노출에서 클릭하게 만드는 제목/썸네일/컨셉”에 집중
  - 광고 붙이고 출시하는 프로세스 공장화

### 안전집사 / 모인 / 점신
- 안전집사: 앱인토스에서 신규 고객 99%, 월 매출 40배 성장 사례 공개
- 모인: 앱인토스 연동 후 신규 가입자 약 40% 증가 언론 보도
- 점신: 예상치 6배 이상의 일간 이용자 기록 언론 보도
- 공통점:
  - 이미 존재하는 니즈/서비스를 토스 유입으로 확장
  - 생활·편의·운세처럼 토스 앱 안에서 가볍게 열어볼 명분이 있음

## 2. 앱인토스 홈 개편이 주는 힌트

공식 업데이트에 따르면 토스 앱 [전체 탭] > [미니앱/게임] 홈에는 다음 구좌가 존재한다.

미니앱 홈:
- 피쳐드 영역
- 실시간 인기 미니앱
- 오늘의 추천
- 카테고리별 인기 미니앱
- 새로운 미니앱
- 포인트 주는 미니앱

게임 홈:
- 게임 카테고리 영역
- 실시간 인기 게임
- 꾸준히 사랑받는 게임
- 유저가 많이 한 게임 카테고리
- 따끈따끈 신작
- 카테고리별 인기 게임
- 내 또래가 많이 플레이한 게임(연령, 성별 기반)

시사점:
- 출시 초기에는 “새로운 미니앱/신작” 구좌를 탈 수 있다.
- 초반 클릭률/체류시간/재방문/공유가 중요할 가능성이 크다.
- 게임은 별도 홈과 랭킹 구좌가 많아 성장 기회가 큼.
- 비게임은 트렌드/혜택/즉시 효용이 있어야 실시간 인기 진입 가능성이 커진다.

## 3. 성공 앱의 공통 공식

1. 제목만 보고 누르게 한다.
   - 거지키우기, 두쫀쿠맵, 방 치우다 현타 와서 만든 판매 사진 앱 등
   - 추상적 앱명보다 상황/결과/호기심이 강한 이름이 유리

2. 10초 안에 첫 보상을 준다.
   - 게임: 터치/합성/점수
   - 지도: 재고 확인
   - 할인: 쿠폰 확인
   - 테스트: 결과 예고

3. 설치 없는 환경에 맞게 “한 번 쓰기 좋은 앱”이어야 한다.
   - 무거운 가입/설문/설정은 불리
   - 토스 로그인도 초반부터 강제하기보다 필요 시점에 사용

4. 반복 루프가 있어야 한다.
   - 매일 미션, 매일 퀴즈, 매일 운세, 매일 할인, 매일 재고

5. 수익화 지점이 UX와 충돌하지 않아야 한다.
   - 결과 보기 전/후 전면 광고
   - 힌트/이어하기 리워드 광고
   - 긴 체류 화면 배너
   - 고급 리포트/광고 제거 IAP

## 4. 머니루틴 계열 차별화 고민

기존 “돈관리/루틴/절약” 앱은 많을 가능성이 높다. 단순히 “돈을 아끼자”로는 약하다.

차별화 방향:

### 방향 A: 절약이 아니라 “돈 새는 구멍 찾기 게임”
- 후킹: “오늘도 3천 원 샜습니다. 어디서 샜을까요?”
- 사용자는 퀴즈/상황 선택으로 자신의 낭비 패턴을 찾는다.
- 결과는 “배달 누수형”, “구독 방치형”, “할인 착각형”, “편의점 자동결제형”처럼 공유 가능한 캐릭터화.

### 방향 B: 토스스러운 “1분 진단 → 바로 행동”
- 후킹: “1분 만에 내 돈 새는 습관 1개만 잡기”
- 긴 가계부가 아니라 오늘 한 가지 행동만 제안.
- 예: 구독 확인하기, 배달앱 지우기, 커피 쿠폰 쓰기, 냉장고 파먹기.

### 방향 C: 실전 혜택 큐레이션과 결합
- 디스팟처럼 할인/쿠폰/생활 혜택을 섞으면 “재미 + 실익”이 생김.
- 단, 금융상품/광고성 오인/외부 링크 정책 주의 필요.

### 방향 D: 게임화
- “거지키우기”처럼 캐릭터 성장 구조를 붙인다.
- 예: 돈 새는 구멍을 막으면 저금통 캐릭터가 성장.
- 광고 보기로 추가 미션/힌트/꾸미기 획득.

## 5. 추천 피벗 컨셉

### 1순위: 돈 새는 구멍 테스트
한 줄: “내 월급은 어디서 새고 있을까? 60초 만에 누수 유형 진단”

MVP:
- 8~10문항 테스트
- 6개 누수 유형 결과
- 오늘의 처방 1개
- 결과 카드 공유
- 결과 후 광고
- 다음 날 다른 테스트/미션으로 재방문

강점:
- 개발 빠름
- 후킹 강함
- 공유 가능
- 정책 리스크 비교적 낮음
- 이후 머니루틴/챌린지로 확장 가능

### 2순위: 돈 새는 구멍 막기 클리커
한 줄: “터치해서 돈 새는 구멍을 막고 저금통을 키우세요”

MVP:
- 터치/클리커
- 누수 구멍 제거
- 저금통 성장
- 일일 미션
- 리워드 광고로 부스터

강점:
- 게임 홈/실시간 게임 노출 가능성
- 광고 수익화와 궁합 좋음
- 거지키우기 성공 공식을 생활비 버전으로 비틀 수 있음

리스크:
- 게임 밸런스/재미 구현 필요
- 너무 카피처럼 보이지 않게 세계관 필요

### 3순위: 오늘의 헛돈 방지 퀴즈
한 줄: “매일 5문제, 틀리면 오늘도 헛돈 씁니다”

MVP:
- 매일 퀴즈 5개
- 점수/랭킹/연속 출석
- 힌트 리워드 광고

강점:
- 반복 구조 좋음
- 개발 난이도 낮음

리스크:
- 콘텐츠 품질이 핵심

## 6. 지금 가장 좋은 결론

바로 순위권을 노리려면 “머니루틴”이라는 착한 이름보다 더 강한 후킹이 필요하다.

추천 네이밍 후보:
- 돈 새는 구멍 테스트
- 내 월급 누수 진단
- 헛돈 탐지기
- 돈구멍 막기
- 월급 도둑 찾기
- 오늘의 헛돈 방지
- 3천원 샜다
- 지갑 구멍 막기

추천 MVP 네이밍:
- `돈 새는 구멍 테스트`

추천 확장 브랜드:
- 앱 이름은 후킹형으로 시작하고, 내부 세계관/리텐션 명칭을 `머니루틴`으로 사용한다.

예:
- 외부 노출명: 돈 새는 구멍 테스트
- 내부 기능명: 오늘의 머니루틴
- 결과 유형: 배달 누수형, 구독 방치형, 할인 착각형, 야식 충동형, 편의점 새는형, 택시 합리화형

## 7. 다음 실험 설계

1. 토스 앱에서 실제 [미니앱/게임] 인기 화면을 스크린샷으로 확보한다.
2. 상위 20개 앱의 이름/카테고리/썸네일/첫 화면/광고 구조를 수집한다.
3. 후킹 문구 10개를 만든다.
4. 가장 클릭하고 싶은 이름 3개를 고른다.
5. WebView MVP를 1~2일 안에 만든다.
6. 출시 후 CTR, 첫 화면 이탈률, 결과 도달률, 공유율, 광고 노출당 수익을 본다.
