# Apps in Toss 리서치 브리프

조사일: 2026-05-02
공식 문서: https://developers-apps-in-toss.toss.im/
LLM 문서: https://developers-apps-in-toss.toss.im/llms.txt, https://developers-apps-in-toss.toss.im/llms-full.txt

## 1. 플랫폼 핵심

Apps in Toss는 파트너 서비스가 토스 앱 내부에서 앱인앱 형태로 노출되는 미니앱 플랫폼이다.

핵심 가치:
- 3,000만 누적 토스 사용자에게 노출 가능
- WebView 또는 React Native 기반 SDK 제공
- 로그인, 결제, 인증, 광고, 푸시/알림, 프로모션, 분석, 정산까지 제공
- 토스 디자인 시스템(TDS), 피그마 UI Kit, 앱빌더 제공
- 출시 서비스는 토스 전체 탭 홈/검색/카테고리 등에 노출 가능

## 2. 서비스 오픈 흐름

공식 프로세스:
1. 시작: 정책 확인, 콘솔 가입, 앱 등록
2. 디자인: 앱빌더 또는 피그마/TDS로 디자인
3. 개발: WebView 또는 React Native SDK/API로 구현
4. 검수: 운영 검수, 기능 검수, 디자인 검수, 보안 검수
5. 출시: 승인 후 콘솔에서 출시

검수 평균 소요:
- 보통 2~3일

앱 등록 승인:
- 보통 영업일 기준 1~2일

일반 개발 소요 FAQ:
- 게임: 약 2~4주
- 비게임: 약 1~3개월

## 3. 중요한 정책/제한

출시 불가 가능성이 큰 영역:
- 디지털 자산/가상자산/NFT
- 현금 또는 유사 자산 교환/전환/환불 구조
- 불법/부정행위 조장
- 사행성, 복권, 베팅성 콘텐츠
- 대출, 보험, 카드, 증권 등 금융상품 중개/판매/광고
- 투자 자문, 리딩방, 유료 투자 정보
- 비대면 진료, 병원 예약, 병원 광고비 수취 구조 등 의료 연결형 서비스

주의 카테고리:
- 의료 정보는 공공데이터 기반 단순 조회만 가능성이 있음. 추천/순위/예약/광고비 수취는 위험.
- 쇼핑몰은 고객센터, 가품 방지, 환불 정책 필요.
- 교육은 국가 전문/기술 자격증 없이 수익 발생 시 제한 가능.
- 데이팅/만남/소셜/채팅/AI챗/민감 콘텐츠/정치/웹보드 게임은 별도 주의사항 존재.

우리 초기 전략:
- 금융상품/투자/의료/사행성/현금성 리워드/데이팅은 피한다.
- 토스 사용자 맥락과 맞는 실용·생활·습관·생산성·가벼운 게임이 안전하다.

## 4. 개발 스택 선택

### WebView
- 명령어: `npx create-ait-app <app-name>`
- 빠른 MVP에 적합
- 기존 웹 기술/React/Vue 등 활용 가능
- `granite.config.ts`에 appName, displayName, icon, primaryColor 등 설정
- 비게임 미니앱은 TDS 사용 필수

### React Native
- Granite 기반 스캐폴딩 필요
- 네이티브 느낌, 성능, 모바일 UX가 중요할 때 유리
- TDS React Native 사용 필요
- 테스트는 샌드박스 앱에서 해야 함

초기 추천:
- 먼저 WebView로 빠르게 MVP 제작
- 반응이 있으면 React Native 또는 고도화 검토

## 6. 주요 SDK/API 기능

인증/식별:
- 토스 로그인 `appLogin`
- 게임 유저 식별키 `getUserKeyForGame`
- 비게임 익명키 `getAnonymousKey`
- 토스 인증: 본인확인/원터치 인증

콘텐츠/성장:
- 인앱 광고: 배너, 전면, 리워드
- 공유 링크/메시지 공유
- 연락처 기반 공유 리워드
- 게임 프로필 & 리더보드
- 토스 포인트 프로모션
- 스마트 발송/푸시/알림
- OG 이미지
- 세그먼트

수익화:
- 인앱 광고: 출시 첫날부터 빠른 수익화 가능
- 인앱 결제: 소모성/비소모성 상품, 광고 제거, 프리미엄 기능, 힌트 등
- 토스페이: 실물 상품/서비스 결제. 입점 심사 및 계약, 키 발급 7~14영업일 고려
- 정산

분석:
- 페이지 이동 자동 기록
- 클릭/노출 이벤트는 직접 로깅
- SDK 0.0.26 이상 필요
- 실제 런칭 다음 날부터 분석 화면 집계

## 7. 수익화 관점

가장 빠른 수익화:
- 인앱 광고
- 특히 반복 사용·결과 확인·게임/퀴즈/진단형 앱과 잘 맞음

광고 유형:
- 배너: 노출 수 많음, eCPM 낮음, 메인/리스트/긴 체류 화면
- 전면: 화면 전환·결과 직전/직후, eCPM 중간
- 리워드: 사용자가 선택, eCPM 높음, 추가 기회/힌트/보상 제공

추가 수익화:
- 인앱 결제: 광고 제거, 프리미엄 기능, 힌트/이용권, 고급 리포트
- 토스페이: 실물/서비스 결제형으로 확장 가능하지만 초기 MVP에는 무거움

## 8. 초기 아이데이션 기준

좋은 아이디어 조건:
- 토스 사용자 맥락: 돈/생활/혜택/시간관리/자기개선과 자연스럽게 연결
- 정책 안전: 금융상품 추천·투자 조언·현금성 전환 없음
- 짧은 세션: 토스 앱 안에서 30초~3분 안에 가치 전달
- 반복 방문: 매일/매주 체크할 이유
- 공유/바이럴: 결과 카드, 친구 초대, 리워드 구조 가능
- 수익화: 광고 지점이 자연스럽고 인앱 결제 확장 가능
- 개발 난이도: WebView MVP 가능, 서버 최소화 가능

## 9. 유력 후보

### A. 하루 1분 돈습관 챌린지
- 컨셉: 매일 하나의 작은 생활비/소비 습관 미션을 수행하고 연속 기록을 쌓는 앱
- 장점: 토스 맥락과 강하게 맞음, 금융상품 중개가 아니라 습관/교육이라 안전성이 높음
- 기능: 오늘의 미션, 체크인, 연속 기록, 친구 공유, 주간 리포트
- 수익화: 배너 + 주간 리포트 전면광고 + 프리미엄 챌린지/광고 제거
- 리스크: 투자/금융상품 추천처럼 보이면 안 됨. 절약 팁은 일반 생활 정보로 제한

### B. 영수증 없이 쓰는 소비 MBTI/소비 성향 테스트
- 컨셉: 짧은 질문으로 소비 성향을 진단하고 결과 카드를 공유
- 장점: 개발 쉬움, 바이럴 강함, 첫 MVP 빠름
- 기능: 10문항 테스트, 결과 유형, 맞춤 미션, 공유 이미지
- 수익화: 결과 보기 전/후 전면광고, 추가 상세 리포트 IAP
- 리스크: 너무 단발성일 수 있음. 매주 새로운 테스트/챌린지로 반복성 필요

### C. 30초 미니 퀴즈: 생활비 절약/상식 게임
- 컨셉: 매일 5문제 생활 상식·절약 퀴즈. 리더보드와 연속 출석
- 장점: 광고/리워드/리더보드와 잘 맞음, 게임 개발 난이도 낮음
- 기능: 퀴즈, 점수, 리더보드, 힌트, 리워드 광고로 이어하기/힌트
- 수익화: 리워드 광고 중심 + 배너 + 광고 제거
- 리스크: 퀴즈 품질과 저작권/정확성 관리 필요

### D. 오늘의 할 일/루틴 스탬프
- 컨셉: 초간단 루틴 체크, 친구와 공유, 주간 성공률
- 장점: 공식 weekly todo 예제를 활용하기 쉬움
- 수익화: 광고는 가능하지만 돈 맥락/토스 특화가 약함
- 리스크: 차별화 약함

### E. 지역/동네 하루 코스 추천
- 컨셉: 현재 위치 기반으로 1~2시간 산책/카페/장소 코스 추천
- 장점: 위치 API 활용, 콘텐츠 확장 가능
- 수익화: 광고/제휴/토스페이 확장 가능
- 리스크: 데이터/콘텐츠 준비가 무거움. travel-app과 프로젝트 맥락 충돌 가능

## 10. 1차 추천

추천 MVP: C + A를 결합한 `머니루틴 퀴즈` 또는 `돈습관 1분 챌린지`

이유:
- 토스 유저 맥락과 잘 맞음
- 정책상 금융상품 판매/중개가 아니라 생활 습관·교육·퀴즈로 안전하게 설계 가능
- WebView로 빠르게 개발 가능
- 광고 배치가 자연스러움
- 매일 반복 방문 구조 가능
- 공유/리더보드/프로모션/푸시 확장 가능

MVP 범위:
- 랜딩/오늘의 미션
- 5문제 퀴즈 또는 1개 챌린지
- 결과 화면
- 연속 기록/점수 저장
- 공유 버튼
- 광고 자리 설계
- 이벤트 로깅

2차 확장:
- 리워드 광고로 힌트/추가 문제
- 리더보드
- 주간 리포트
- 인앱 결제: 광고 제거/프리미엄 챌린지팩
- 스마트 발송: 오늘의 미션 알림

## 11. 다음 액션

1. 후보 중 하나를 선택한다.
2. 앱 이름/appName/카테고리/아이콘 컨셉을 정한다.
3. `npx create-ait-app <app-name>`으로 WebView 프로젝트를 생성한다.
4. TDS + AI Skills + 광고/공유/로깅 예제를 포함해 스캐폴딩한다.
5. 정책 위험 체크리스트를 먼저 문서화한다.
6. 1주 MVP를 만든다.
